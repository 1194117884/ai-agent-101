# Agent Teacher MVP 实施 Todo

## 目标

把现有两份课程网页升级为一个单人 Agent Engineering 私教：能够基于学习证据诊断能力、分派下一步任务、在线答疑、组织小测、分析薄弱项，并随课程资料更新知识。

## 产品边界

- 首版服务对象：一个已登录的学习者。
- 首版入口：Web，不接飞书、Telegram、Discord。
- `agent_30_day_bootcamp.html`：能力地图、练习和验收素材来源。
- `agent_30_day_bootcamp_v2.html`：唯一的默认教学路径与阶段划分来源。
- 30 天是默认节奏；任务由掌握证据和前置依赖动态调整，不按日期强制推进。

## P0：统一课程与能力模型

- [x] 把 v2 的五阶段和 Day 1–30 节奏整理为结构化课程数据。
- [x] 从基础划分页提取 18 个知识点、项目、阅读材料与验收要求。
- [x] 为每个课程单元绑定：主题、前置主题、学习目标、阅读、练习、验收标准、资料来源。
- [x] 解决两版阶段日期冲突：以 v2 为路径，原版只提供能力/练习/验收信息。
- [x] 为每条资料保存 URL、发布或版本日期、抓取/录入日期、可信等级和适用主题，并向 Coach 提供时间溯源。

完成标准：系统可查询任一知识点的前置能力、相关课程单元、练习、验收要求和来源。

## P0：学习者状态与能力画像

- [x] 创建学习者基础资料与 Web 设置：目标、每周投入时间、时区、当前项目、偏好节奏。
- [x] 创建 `competency_state`：主题、掌握度、置信度、最后评估时间、遗忘复习时间。
- [x] 创建 `evidence`：作业提交、代码链接、笔记、对话回答、小测结果、教师反馈。
- [x] 创建 `learning_task`：任务目标、关联主题、前置条件、状态、预期产出、验收 rubric。
- [x] 以学习证据更新掌握度；禁止仅凭“已读/已打卡”判定掌握。

完成标准：系统能解释“为什么判断该主题薄弱”，并展示支撑该判断的证据。

## P0：教师 Agent 核心循环

- [x] 定义并展示教师 Agent 的结构化输出：`diagnosis`、`feedback`、`next_task`、`question`；能力变化仍由正式评分证据控制。
- [x] 为教师答疑提供只读上下文：课程检索、能力画像、最近证据、资料来源、当前任务和近期对话。
- [x] 提供受控写入接口：提交或小测后原子记录评分证据、更新能力状态并调整下一任务。
- [x] 实现标准 tool-call 循环，保留每个 tool-use ID 并回传对应结果；首批仅开放学习状态与课程单元两个只读工具。
- [x] 让答疑先分类：概念不清、前置缺失、实现路径、调试、范围过大；再选择追问、提示或示例，并在回答中显示分类。
- [x] 让任务生成遵循“一个最小下一步 + 明确产出 + 可验收标准”；按掌握度、置信度、优先级与前置能力动态选择下一项评估。

完成标准：用户提交一次回答或作业后，Agent 能引用当前课程与历史证据给反馈，并生成下一步可执行任务。

## P1：评估与薄弱项分析

- [x] 为主题建立题型：概念口试、情境选择、设计题、代码审查、trace 分析、项目验收。
- [x] 为每题和每个作业建立 rubric，区分正确性、解释能力、工程权衡和可复现性。
- [x] 实现小测会话：按薄弱能力出题、接收答案、按 rubric 评分、保存正式证据，并重新安排下一任务。
- [x] 计算薄弱项：覆盖低分、重复低分、低置信度、前置缺失、遗忘风险和任务长期卡住，并在能力画像展示判断依据。
- [x] 生成阶段报告：已掌握、待巩固、薄弱项、下一阶段建议，并展示近期评分证据。

完成标准：系统能在至少三个主题上用真实提交生成带证据的薄弱项报告，而不是只显示完成率。

- [x] 增加提交入口：文本、笔记、代码片段、URL。
- [x] 增加教师对话区，显示任务上下文和资料引用。
- [x] 增加能力画像：主题掌握度、证据、薄弱原因、复习建议。
- [x] 增加测验界面与阶段报告。

## P2：知识更新与主动教学

- [x] 建立资料录入流程：管理员上传文件、人工添加 URL 或受控抓取可信源。
- [x] 保存摘要、原文片段、版本、主题映射和来源链接；管理员录入后自动发布，失败时保留重试入口。
- [x] 课程回答显示引用、相关性、资料版本和可信等级；资料冲突时明确提示并给出选择依据。
- [x] 实现复习提醒、停滞提醒和基于个人投入的周计划；先在 Web 通知中心实现。
- [ ] 只在用户确认后接入一个外部消息渠道。

完成标准：新增一篇官方资料后，教师能够在相关答疑中检索并引用它，且不改变已确认课程的默认路径。

## 暂不做

- [ ] 多学生管理和管理员面板。
- [ ] 三渠道适配器并行接入。
- [ ] 自动执行不受信任的学生代码。
- [ ] 无来源、无审核的自动网页知识抓取。

## 推荐实施顺序

1. P0 课程模型与能力画像。
2. P0 教师 Agent 核心循环。
3. P1 评估和薄弱项分析。
4. P1 Web 闭环。
5. P2 知识更新和主动提醒。
