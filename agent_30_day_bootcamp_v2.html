教学哲学

为什么这样设计

能力闭环优先于知识覆盖

读书不是主线，能闭环才是主线。每个阶段都必须产出可运行、可评估的代码，而不是停留在「我看懂了」。

一个 Runtime，多次迁移

不是并行做四个完整产品，而是把同一组 Agent 原语反复迁移。每次迁移都是一次「抽象是否正确」的测试。

Eval 从第一天开始

没有评估就没有工程。Day 1 就要求最简 eval，后续阶段只是在升级评估体系的复杂度。

Context 是一等公民

把 Context 当作有限资源来管理，是 2025–2026 Agent 工程的核心能力。本课程把它提升到与 loop / tool 同等重要的位置。

1

基础与单 Agent Runtime

Day 1 – 6

学习目标

  • 建立正确的 Agent 心智模型（Workflow vs Agent）
  • 用最薄实现跑通完整 loop：感知 → 推理 → 行动 → 观察
  • 理解 Tool 的本质与描述质量的重要性
  • 从第一天就建立「可评估」的习惯

关键产出

  • 一个可运行的单 Agent Runtime（直接 API 或最薄 SDK）
  • 至少 3 个高质量 Tool + 描述
  • 最简 Eval 套件（固定测试集 + pass rate + 基础 trace）
  • Lab 日志：每天记录「今天改了什么、为什么、结果如何」

阅读材料

必读 · Building effective agents (Anthropic) 必读 · ReAct 论文 必读 · Agentic Design Patterns（Prompt Chaining / Tool Use 章节） 研学 · OpenAI Practical Guide（前半部分） 研学 · Toolformer 论文
Lab 重点：不要追求功能多，追求「loop 清晰、tool 描述干净、每次运行都能留下可复现的 trace」。这是后面所有阶段的地基。
2

Context Engineering 核心

Day 7 – 11

学习目标

  • 把 Context 当作有限、昂贵、会衰减的资源来管理
  • 掌握 Tool 设计的 UX 原则（命名、描述、返回信号、token 效率）
  • 理解 Agent Skills 的渐进披露与组合方式
  • 学会在有限窗口内保持高信号密度

关键产出

  • 重构后的 Tool 层（描述更精准、返回更干净）
  • 一套可加载的 Skills（至少 2 个）
  • Context 管理策略文档（什么该留、什么该清、什么该外置）
  • 对比实验：优化前后 token 消耗与成功率变化

阅读材料

必读 · Effective context engineering for AI agents 必读 · Writing effective tools for agents 必读 · Equipping agents with Agent Skills 必读 · MCP Spec 2026-07-28（Architecture / Tools / Resources） 研学 · Agentic Design Patterns（Memory 相关章节） 兴趣 · Voyager（skill library 部分）
Lab 重点：这一阶段是整个课程的战略高地。宁可少做功能，也要把「Context 如何被管理」想清楚、写清楚、测清楚。
3

Reasoning · Reliability · 初步编排

Day 12 – 17

学习目标

  • 深入理解 ReAct 循环及其在现代系统中的变体
  • 掌握错误恢复、重试、终止条件设计
  • 能做简单的多步编排与状态管理
  • 在第 16–17 天引入最简 Multi-Agent（orchestrator-worker）

关键产出

  • 带恢复机制的可靠 loop
  • 明确的终止 / 升级 / 回退策略
  • 一个最小可用的 orchestrator + 1–2 个 worker
  • 更新后的 Eval：加入多步任务与失败恢复场景

阅读材料

必读 · ReAct（精读） 必读 · Reflexion 论文 必读 · Agentic Design Patterns（Planning / Exception Handling / Multi-Agent 章节） 研学 · How we built our multi-agent research system 研学 · OpenAI Agents SDK · Orchestration 部分 兴趣 · SWE-agent（ACI 思想）
Lab 重点：Multi-Agent 只做「必要的复杂度」。如果单 Agent + 好工具能解决，就不要上 Multi-Agent。第 17 天再决定是否真正引入。
4

Eval · Harness · Security

Day 18 – 24

学习目标

  • 建立完整的 Agent 评估体系（task / trial / grader / trace / outcome）
  • 掌握长运行 Agent 的 Harness 设计（initializer + worker + progress artifacts）
  • 理解 Containment 与 blast radius 的基本思路
  • 能做有意义的 Ablation 实验

关键产出

  • 可复用的 Eval Harness
  • 支持跨 session 的 Long-running Harness
  • 基础 Sandbox / 权限边界设计
  • 至少 2 组 Ablation 结果（去掉某组件后的性能变化）

阅读材料

必读 · Demystifying evals for AI agents 必读 · Effective harnesses for long-running agents 必读 · Harness design for long-running application development 研学 · How we contain Claude across products 研学 · τ-bench / AgentBench（评估方法论） 兴趣 · 完整安全与威胁模型章节（O’Reilly / Design Patterns）
Lab 重点：这是从「能跑」到「能长期可靠跑」的关键跃迁。Harness 和 Eval 的质量将直接决定 Capstone 的上限。
5

Capstone 产品化

Day 25 – 30

学习目标

  • 把同一个 Runtime 迁移到至少两个真实场景
  • 用 Ablation 验证核心设计决策
  • 产出可展示的最终 Benchmark 结果与复盘
  • 形成自己的「Agent 工程检查清单」

关键产出

  • 迁移后的可运行系统（至少 2 个场景）
  • 完整的 Ablation 报告
  • 最终 Eval 报告 + 已知局限
  • 个人 Agent 工程笔记 / 检查清单

阅读材料

必读 · 回顾所有必读材料，形成自己的总结 研学 · AI Agents in Action / Definitive Guide 中与 Production 相关的章节 兴趣 · 根据个人方向深挖（SWE / 多 Agent / 安全等）
Lab 重点：Capstone 不是「再做一个大功能」，而是「验证你这 24 天建立的抽象是否经得起迁移和拆解」。

设计说明（相对原版的调整）

1. Context Engineering 前置并升权

原版把 Context 与 Memory 并列在 Day 7–12。修订版单独抽出 5 天，作为战略重点，因为这是当前生产 Agent 最容易踩坑、也最有杠杆的地方。

2. Eval 从 Day 1 开始埋种子

不再等到 Day 19 才系统讲评估。从第一天就要求最简 eval，后续只是升级复杂度，避免「写了很多却无法衡量」。

3. Harness / Long-running 获得完整阶段

长运行能力是区分「玩具 Agent」和「可用 Agent」的关键。修订版给足时间，并强制做跨 session 实验。

4. 阅读材料分层更锋利

明确必读 / 研学 / 兴趣三层，避免 30 天里平均用力。学生知道什么必须掌握，什么可以按兴趣深挖。

本修订版基于原 30 天大纲的优秀哲学，针对 2026 年 Agent 工程实践做了节奏与优先级调整。
核心不变：一个 Runtime · 多次迁移 · 能力闭环 · 评估驱动。
